# LabVIEW → MATLAB

用真实源证据交付可追溯的 MATLAB 函数或驱动。先复用已有解析和生成工具，按用户当前目标选择处理路径，不把某次项目的阶段审批推广成所有任务的固定流程。

## 选择处理路径

- **IR 自动生成**：用户要求证明真实 IR → MATLAB 时，使用真实解析结果及生成器；新增能力应按节点语义实现。不能按 VI 名称或源哈希匹配固定函数体，不能手写目标函数后标成自动生成。
- **工程化改写**：仅在用户授权时，依据实际 Block Diagram、源命令、适用 API 契约重写不支持的部分。将自动生成与改写文件分开标识，逐项记录语义差异；不强制先扩展 Schema。
- **只读分析或计划**：按授权交付诊断、设计或可行性报告，不借机开始实现。

若目标不清楚，只询问会影响路线的事项。已有任务范围和授权持续有效，不重复索要逐 VI 批准。

## 工作顺序

1. 定位工程、既有工具、解释器和输出目录。只查看相关入口、Schema、候选 VI 和依赖，不先扫描所有历史产物。
2. 保存源文件 SHA-256 与工具版本；确认原工程只读、输出隔离。哈希用于追溯，不证明行为或型号兼容。
3. 用实际 Python API 取得结构化 VI 数据，保留 metadata、接口、节点、端子、连线、嵌套结构、类型和 Block Diagram 的 SubVI 调用。CLI 文本和工程 Dependencies 不能替代这些证据。
4. 选最小可实现的真实候选及其依赖闭包。区分“解析／IR 缺失”与“生成器暂不支持”；不因无关 VI 失败而修复整个工程。
5. 核实 Connector Pane、类型、数据流和调用绑定。源值未知时继续标未知；证据缺失会影响正确性时，明确阻塞项。
6. 自动生成路径从完整 IR 生成；工程化路径保留命令及参数来源。每个文件标明来源类别、依赖、接口和限制。
7. 在授权范围内验证并报告：静态检查、Python 回归、实际 MATLAB Fake 执行、人工硬件测试分别记账。没有实际运行就不能写“通过”。
8. 交付独立输出目录、使用说明、源映射及结果；保留旧产物，不覆盖历史证据。

处理步骤和工具边界见 [workflow.md](references/workflow.md)。

## 必须保持的语义

- 稳定关联 node、wire、terminal；保留 source/destination 和 structure 层级，不把嵌套执行域展平。
- 接口顺序来自真实 Connector Pane 或等价可核查证据，不能使用文件名、画面坐标、节点遍历顺序或端子局部索引猜测。
- Connector Pane 物理槽位保留原值；输入、输出分别按已确认槽位升序分配连续 MATLAB 参数位置，记录对应表。
- SubVI 调用节点关联和实参／形参绑定分别验证；相同调用的多个输出共享一次求值。
- 未知／不支持节点保留 metadata 和 diagnostics；不能静默删除、填零、固定返回或吞异常伪装成功。
- 严格核对数据边类别、方向、唯一生产者、类型、常量完整性、输出定义、错误流和副作用顺序。
- 字符串命令、格式、单位、标点和终止符来自源 VI。别的型号手册不能代替源工程命令。

详细规则见 [semantics.md](references/semantics.md)。

## 仪器及验证边界

默认离线。只有用户明确授权的硬件动作才能创建真实会话；离线 Fake 不调用 visadev、NI-VISA、USB 或网络会话 API。把设备地址集中配置；用户交付流程中的实际波形输出需要显式启用。

不要把 Python 契约测试、MATLAB 实际执行、真实 VISA 通信、仪器功能正确性和型号兼容性混为一个结论。源模式未知时，目标等待策略是有范围的转换选择，不能声称 LabVIEW 线程／实时性能等价。

按用户要求的验证层级使用 [validation.md](references/validation.md)。需要复用本项目环境及案例经验时，阅读 [project-notes.md](references/project-notes.md)；其中的历史结果不可当成本次验证结果。

## 停止与交付

关键接口、类型、命令或执行顺序无法从真实材料确认，或需要超出授权修改原始工程／显著扩大语义范围时，说明最小阻塞项与所需材料。常规实现选择、局部修复和文档整理在已有授权内继续。

交付说明至少包括：已实现功能、文件类别、调用接口与示例、命令来源、依赖与环境、实际验证范围、未实现功能的明确失败方式、剩余型号差异。用户只要求方案时，停在方案；阶段限制按当前授权执行。
