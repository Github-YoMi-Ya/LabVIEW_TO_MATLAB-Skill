# 分层验证与交付记录

按用户授权选择验证层级；用户只要求整理文档时不运行项目测试或 MATLAB。没有执行的验证明确写“未运行”。

| 层级 | 能证明 | 不能证明 |
|---|---|---|
| 源／IR 检查 | 证据对应、接口与图关系、哈希一致性 | MATLAB 执行正确 |
| Python 回归与 Fake 契约 | 解析和生成器行为、文本约束、Python 模型结果 | 已执行生成的 MATLAB |
| 实际 MATLAB + 内存 Fake | `.m` 的语法、分派、数据传递和受测行为 | 真实 VISA、设备响应、型号兼容 |
| 真实仪器测试 | 指定环境、设备、参数下的实际结果 | 全工程等价或所有固件兼容 |

## Python

先确认指定解释器的实际依赖可导入并记录版本；不要因 PATH 顺序误用 MSYS Python。需要全量回归时在原项目布局使用正式入口 `tests/run_tests.py`，记录解释器、工作目录、完整命令、退出码和通过／失败数量。

依赖缺失属于环境问题，断言与实现不一致属于待分析的问题；不能跳过、削弱测试或只保留成功日志。依赖按实际用途声明：本项目的 jsonschema 参与运行时 IR 验证，因此属于运行依赖。

新候选加入时回归已有候选；如果只修改依赖声明而生成器与产物字节未变，无需自动重复已通过的 MATLAB 执行。影响生成内容时，生成到新目录并重跑受影响案例。

## 实际 MATLAB Fake

Fake 使用纯内存 handle 对象记录事件，write、wait 等接口实现为记录和确定性异常注入。它不创建 visadev、旧 visa、NI-VISA、USB、TCP/UDP 或其他真实通信会话。

直接加载并调用生成器实际输出的 `.m`，记录路径与 SHA-256，防止同名函数或手写替身遮蔽目标。保留 MATLAB 版本、启动命令、退出码、逐项断言和日志。

适用项：精确命令（含 CR/LF）、数值边界与格式、调用次数、SubVI 参数绑定、写入→等待顺序、错误短路、warning 保留、异常转换、输出与资源 handle 身份。

模拟超时通过注入异常验证错误路径，不等于测试真实计时超时。Fake 等待可记录时长与顺序，不证明实时性能。使用 Fake 的实际 MATLAB 执行与只在 Python 中建模要在报告里分开。

## 环境故障

MATLAB/VISA 故障先记录版本、DLL 与错误事实，再区分安装环境与代码缺陷；不把重装或升级系统当作技能默认动作。缺少 MATLAB 就报告缺失，不安装，不编造实际运行结果。

项目曾遇到 `VISACM_GetInstalledVisaCount2` 缺失：旧 NI-VISA／Conflict Manager DLL 与 MATLAB 组合不匹配。这个经验用于提示检查加载链，不是以后出现任何 VISA 错误都要升级的规则。修复安装需单独明确授权。

- 结果：各层实际运行内容、命令、退出码、断言及日志位置。
- 限制：未知语义、目标策略、型号差异、未运行的层级、硬件通信状态。
- 完整性：原始文件未修改，旧产物保留；失败时最小阻塞项及所需材料。
