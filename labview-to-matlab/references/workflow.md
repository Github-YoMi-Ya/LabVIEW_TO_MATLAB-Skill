# 证据与处理流程

## 先确定产物

最小交付可以是一个真实 VI 及其依赖，也可以是用户明确授权的首批驱动功能。不要因为整个工程尚不能解析就无限延期；也不要把部分成功写成全工程完成。

为候选记录：源相对路径与 SHA-256、解析器版本、完整 IR 路径与哈希、接口证据、直接依赖和未知项。Golden 的摘要只用于回归对比，不能当作完整 IR。

## 分层处理

| 层 | 需要的事实 | 常见问题与处理 |
|---|---|---|
| 工程清单 | 工程引用、实际文件、路径别名 | 工程 Dependencies 仅作清单，不形成调用图 |
| VI 解析 | Block Diagram 节点、端子、连线、结构、调用 | 通过实际 Python API 获取；低层 XML 不等于完整语义 |
| 数据流与 IR | 稳定 ID、执行域、类型、接口和调用绑定 | 序列化保留未知项、来源和 diagnostics |
| 生成资格 | 支持状态及语义完整性 | 逐实体检查，不用“验证零错误”替代资格判定 |
| MATLAB 生成 | 表达式、一次求值、依赖函数、效果顺序 | 复用通用节点映射，不按名称／哈希写固定函数体 |
| API 适配 | 源命令、资源生命周期、错误与超时 | 仅在工程化改写被授权时实施并标注差异 |
| 验证与交付 | 实际执行记录、已知限制、调用说明 | 区分静态、Python、MATLAB Fake、硬件证据 |

上游证据采集与生成资格检查应分开：先允许在只读范围导出事实，再决定是否能生成，避免“没有完整 IR 不补强、没有补强不能导出 IR”的循环。

## 工具复用

现有工具的结构：`adapters/` → `model/` 与 `parsed_vi.py` → `graph/`、`dataflow/` → `ir/` → `generator/`。CLI 入口为 `python -m labview_to_matlab`。

优先查看当前 `--help` 与实际实现，不以老 README 的阶段描述判断能力。`lvkit` 用于语义图；`pylabview` 提供低层 RSRC/XML 证据，单独回退成功不代表已取得节点／连线语义。

IR 导出支持哪些版本、缺省版本及生成器兼容性需核对当前 CLI 和 Schema。此项目快照的 IR CLI 提供 0.1.0 与 0.2.0，默认仍为 0.1.0；旧版可读不等于满足生成资格。不要臆造字段或静默将旧版缺失值补为已知。

## 输出

- 规范化路径后，输出必须隔离于源 VI／工程目录。解析器可能导出临时文件，运行前核查它是否会写工作目录，必要时使用隔离工作目录。
- 每次使用新的运行目录，记录输入 IR、工具版本、生成文件、报告与日志的关联。
- 先检查所有目标，包括根报告。提交时也要保证不覆盖；同批依赖失败不能留下貌似完整的调用者。
- 保留原产物。若提交失败，记录已创建、回滚和残留项目；只清理本次创建的文件。
- 整理备份时复制已选择的源码和方法，不搬移或删除原工程；未包括的材料明确列出。

## 工程化驱动首版

用户授权快速交付驱动时，可按依赖划分连接／身份／关闭、基础配置、输出开关、错误查询、写入／等待。参数、命令及合法范围仍需真实证据；未实现功能明确抛错。

提供一个集中配置文件和连接测试入口。将连通性检查与会改变仪器输出的动作分开，由显式开关控制实际输出；不要把“示例”默认为用户授权代理连接仪器。
